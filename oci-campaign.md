## Decisions

- **Prescribed — surface and identity:** `myoci mirror resolve`, `plan`, and `sync` are distinct. Require `--config`, `--lock`, and, for plan and sync, `--state-dir`; require `sync --locked`. Provide `--json` for plan and sync, `--offline` for sync, and repeatable `resolve --entry NAME` to refresh selected entries. Resolve without selection refreshes all entries. Selection requires an existing valid lock and must reject a selected name absent from the inventory; preserve unselected entries only when their normalized input and policy are unchanged. An inventory change to an unselected entry fails instead of retaining stale data. Reason: no implicit upgrades or mixed policy state.
- **Prescribed — inventory and lock:** use `deploy/oci-mirror.toml` and `deploy/oci-mirror.lock`, schema and policy version 1, deterministic serialization and normalized inventory fingerprint. Reject unknown fields, duplicate IDs, duplicate aliases, conflicting destination repository/tag assignments, invalid references, and unsupported versions before acquiring content. Sort entries, aliases, platforms, and referrers by their canonical identities. Omit timestamps and run statistics. Record declared source, normalized source repository, root descriptor, explicit destination repository and tags, platform requirements and resolved summary, and each additional referrer descriptor and subject. Do not store the full layer list in the lock. Use a reconstructible cache for graph metadata. Preserve registry and path components in destinations. Normalize Docker Hub shorthand and aliases consistently; do not infer the destination.
- **Prescribed — seed:** initialize entries from the exact digest references in `deploy/manylinux_2_28-amd64` and `deploy/manylinux_2_28-arm64`, with IDs `manylinux-amd64` and `manylinux-arm64`, respective `linux/amd64` and `linux/arm64` requirements, destinations `quay.io/pypa/manylinux_2_28_x86_64` and `quay.io/pypa/manylinux_2_28_aarch64`, and the alias `pinned` for each. Use `referrers = "snapshot"` for both. Add a local consistency check against those files. Keep the pins and consumers unchanged. Generate the committed lock with verified descriptor metadata, never fabricated sizes or media types. If upstream is unavailable, park the seed lock as Needs environment while completing fixture-based local work.
- **Prescribed — graph and referrers:** preserve source bytes and root digest. Walk nested indexes, all supported manifests, config and layers, including index-embedded attestations; verify every digest and size. Required platforms are a minimum, never a filter, and match OS, architecture, and any specified variant. Read a single image's config when needed. Report a missing requirement and unsupported content as errors. `referrers = "snapshot"` observes supported direct referrers for the root, its reachable child manifests, and recursively discovered referrer roots; record subjects and deduplicate. `referrers = "none"` disables only additional discovery. Distinguish an empty observation from unsupported or failed discovery, which fails resolution. Enumeration is an observation, not an atomic historical snapshot. Preserve existing local attachments; the lock is an acquisition minimum, not a deletion list. No signature verification or legacy signature-tag discovery.
- **Prescribed — resource limits and effects:** cap an individual manifest at the existing 4 MiB, graph depth at 32, distinct descriptors at 100,000 per entry, captured subprocess output at 1 MiB, and concurrent ORAS processes at one with ORAS concurrency 3. Set a 30-minute deadline per ORAS invocation and terminate and reap timed-out children. Use at most two attempts only for identified transient network failures; never retry integrity, invalid input, or conflicts. Cap configuration and lock files at 16 MiB each. Exceeding a limit is an explicit error. Pass structured argv, never a shell command, and keep credentials out of logs, URLs, and arguments. Preserve TLS verification; plain HTTP is limited to the local test harness. These defaults bound untrusted registries; change them only on evidence from a supported real graph.
- **Prescribed — acquisition and planning:** resolve mutable tags only during `resolve`, fetch the resolved root again by digest, and verify it. Metadata discovery must not download layer bodies. Locked sync never resolves a tag, rewrites the lock, uses unrestricted recursive referrer discovery, or falls back to a tag. Import by expected digest and walk only that root and recorded referrer roots; retain standalone `import` selection behavior. Use verified state objects with an ORAS-compatible isolated per-job layout or serialized layout metadata. Test `--force` for incomplete graphs; never assume a present root proves completeness. Do not keep a second permanent copy of every layer. Offline sync checks all required content and fails with missing identities if unavailable. Planning is local and read-only, even for a missing state directory; it must not initialize state, render, rebuild referrers, recover a pending transaction, or write publication markers. If a transaction needs recovery, plan fails clearly and directs the operator to a mutating command that performs recovery. Show desired aliases, local conflicts, available and missing objects, and deduplicated known transfer bytes; distinguish unknown estimates from zero and local presence from remote R2 availability.
- **Prescribed — alias transaction:** preserve manual tags, unrelated repositories, adopted content, and all immutable objects. An identical unmanaged alias is idempotent and becomes managed; a different unmanaged mapping is a conflict, with no implicit takeover. A managed alias may move only if its current value equals the last applied value, and only after the entire requested batch is verified. Removing an inventory entry or alias removes neither tags nor objects; relinquish ownership of removed aliases without deleting them. Persist the last applied mapping. An interruption must recover to the complete old or new metadata snapshot before any reader or writer proceeds, never a mixed snapshot. Use a durable staged snapshot and a single durable commit marker, or a journal with equivalent recovery and tests for every write boundary. Immutable content acquired before failure may remain.
- **Prescribed — locking:** one state lock covers recovery, all metadata mutations, and a coherent publication snapshot. Include import, tag, adopt, native push commit, mirror sync, verify/read paths that require a consistent multi-file view, and publish. Acquire state lock before site lock; the deployment wrapper's publish lock remains outermost. Never hold the state lock while downloading. After acquisition, reacquire the lock and revalidate alias expectations before committing. Preserve the writer's existing bounded lock-failure semantics and avoid reentrant lock acquisition through explicit locked internal operations. Publication releases the state lock only after its immutable snapshot is complete.
- **Prescribed — generation and compatibility:** add a versioned, deterministic generation-local provenance and ownership sidecar to the file map *before* computing the generation ID. It includes stable inventory identity, policy, source intent, root, additional referrers, destination and aliases. No timestamps or transient outcomes. Carry unrelated provenance forward on targeted changes. Adopt restores sidecar and ownership; generations without one remain readable and adoptable with no managed aliases. Adopt followed by republish preserves provenance. Keep catalog schema 4, serving paths, rollback reachability, and existing published formats. Do not introduce pruning.
- **Prescribed — publication:** add an explicit, mutually exclusive inventory-and-lock input mode to `deploy/publish oci` and `deploy/publish-myoci.sh`; preserve `OCI_IMAGES`, `OCI_LAYOUT`, and republish behavior. Validate, acquire and verify the batch, commit local metadata, render, sync blobs, sync metadata, then conditionally promote `current`. Preserve stale-publication and dropped-version guards, remote verification, and immutable conflict handling. Repair missing remote objects before reporting success. A remote failure reports local preparation separately from promotion and leaves the previously promoted generation usable; never force past a conflict.
- **Delegated — dependencies and representation:** choose the smallest maintained, Apache-2.0-compatible TOML parser and transaction representation that satisfy these contracts. Inspect license, transitive weight, maintenance and alternatives before adding a dependency; remove unused dependencies. Do not add native acquisition dependencies to `stuff-oci` or the Worker. Preserve `#![forbid(unsafe_code)]`. Measure build time and binary size against the pre-change baseline; also measure startup and runtime when affected. No numerical repository budget is defined: report deltas and reject regressions larger than observed spread unless necessary for a required feature and explained. Time gates run only between successful `perf-gate-ready` and `perf-gate-ready -1` checks; a busy host defers the gate and blocks completion, not iteration. Binary size and memory checks always run.

## Baseline

At `cfc93c8`, `cargo test -p myoci --test cli imported_state_publishes_serves_adopts_and_detects_tampering -- --exact` passed in 7.6 seconds including a partial debug build and 1.50 seconds with warm artifacts. This is a single integration baseline, not a full-suite result. ORAS 1.3.6 is installed. A local OCI-layout copy with `oras cp --force` restored a deliberately removed child manifest while the root remained present. Remote reuse, transfer counts, multi-file recovery, and other checks below are unproven. The existing publisher verifies and renders before acquiring the site lock; rendering rebuilds state referrer files. The existing importer traverses all layout roots and can select the first root as a fallback. Native push currently takes `.push.lock`; other state mutation paths do not share it.

## Sequence

Each acceptance command names a test to create as part of that slice. It must exercise production behavior and fail for the stated regression. Keep the named command in minutes; split the test internally only if needed without weakening the acceptance contract. Add regression tests before fixes when behavior is clear.

1. **M1 — inventory and lock (medium).** Own `crates/myoci/src/mirror*`, `cli.rs`, `lib.rs`, `Cargo.toml`, `Cargo.lock`, mirror integration tests and inventory seed. No prerequisites. Parse, normalize and validate inventory; serialize deterministic versioned locks and check existing seed pins. Implement the command skeleton with explicit errors for operations not yet implemented, without claiming end-to-end sync. Acceptance: `cargo test -p myoci --test mirror inventory_and_lock -- --exact`. Prove strict parsing, normalization, canonical output, duplicate and conflicting aliases, version errors, per-entry platform requirements and seed consistency.
2. **M2 — resolve immutable metadata (large).** Own mirror modules, CLI, and local registry fixture. After M1. Resolve tags and selected entries, verify raw manifests by digest and size, walk complete supported graphs, inspect config when needed, observe referrers, enforce bounds, and atomically replace the lock only after the entire requested resolution succeeds. Acceptance: `cargo test -p myoci --test mirror resolve_snapshots -- --exact`. Prove unchanged lock bytes, targeted refresh, tag A moving to B after lock, no layer-body reads during resolve, nested indexes and variants, discovery failure versus empty result, and failed resolution preserving the old lock.
3. **M3 — read-only plan (medium).** Own mirror modules and CLI. After M2. Plan against inventory, lock, and a state snapshot without writes or network. Acceptance: `cargo test -p myoci --test mirror plan_is_read_only -- --exact`. Compare full state, site and marker trees before and after both successful and failing plans, including absent state. Verify desired aliases, conflicts, missing platforms, deduplicated known bytes and explicit unknowns.
4. **M4 — locked acquisition (large).** Own mirror modules, `import.rs`, `state.rs`, and local registry fixture. After M2. Acquire by exact root and recorded referrer digests, verify full graphs, import expected roots without relying on layout order, and support offline replay. Acceptance: `cargo test -p myoci --test mirror locked_acquisition -- --exact`. Prove A remains A after tag moves to B, unrelated roots do not affect selection, nested indexes and embedded attestations retain root digest, an attachment added after resolve is not acquired, historical attachments remain, missing descendants are repaired with root present, unsupported or corrupt content fails, and offline mode succeeds only with complete local content. Count actual upstream blob-body requests and bytes; the second successful sync transfers zero bodies. Do not require tag changes in this slice.
5. **M5 — atomic aliases and locking (large).** Own `state.rs`, `import.rs`, `push.rs`, `publish.rs`, `cli.rs`, mirror modules and state transaction tests. After M4. Introduce the shared lock and recovery protocol, ownership metadata, conflict checks and all-or-nothing batch alias application. Acceptance: `cargo test -p myoci --test mirror managed_batch_is_atomic -- --exact`. Inject interruption at every durable transaction boundary; restart through each reader and writer and prove old or new complete state. A bad later entry changes no aliases. Exercise stale and unmanaged conflicts, idempotence, inventory removal, concurrent import, push, adopt and publication, and preservation of unrelated updates. Check lock order and bounded contention.
6. **M6 — provenance and adoption (medium).** Own `publish.rs`, mirror and state modules, and publication tests. After M5. Add the generation sidecar before hashing, restore it during adopt, preserve unrelated entries and support old generations. Acceptance: `cargo test -p myoci --test mirror provenance_survives_adoption -- --exact`. Prove provenance-only changes change the generation ID, identical replay does not, adopt → republish preserves ownership and provenance, old generations remain adoptable, and retained generation rollback has all reachable content.
7. **M7 — publication integration (medium).** Own `deploy/publish`, `deploy/publish-myoci.sh`, `deploy/test-oci-publish.sh`, mirror integration tests and `docs/PUBLISHING.md`. After M6. Add explicit mode selection and the ordered local preparation and remote promotion path. Acceptance: `make test-oci-publish`. Extend the local R2 simulation to prove no-op replay, absent remote object repair, conflicting immutable object failure, stale promotion, failure before promotion leaving old `current` usable, and distinct local versus remote outcomes. Assert OCI publication leaves Cargo, npm, and Python outputs unchanged. Keep existing input modes tested. Run the parity milestone in Acceptance after this slice.
8. **M8 — harden and document (medium).** Own `crates/myoci/README.md`, `docs/oci-design.md`, `docs/PUBLISHING.md`, `deploy/oci-mirror.toml`, `deploy/oci-mirror.lock`, focused tests, and only the CI workflow needed for the requested offline validation. After M7. Document exact add, selected refresh, review, locked sync, offline replay, publish, conflict, missing digest, adopt, rollback, initial publication and consumer cutover commands. Add deterministic offline configuration, lock consistency and fixture validation to CI; do not put online resolve or publication in routine sync. Acceptance: `cargo test -p myoci --test mirror operational_contract -- --exact`. Prove the documented commands and all success and failure conditions against fixtures. Execute any runnable documentation examples in the local fixture environment.
9. **M9 — optimize and close (medium).** Own only files shown by profiling and tests already in scope. After M8. Use a substantive mirror replay as the pilot; measure before changing it. Preserve the functional contracts and zero second-sync blob bodies. Apply the dependency and time-gate rules above; compare interleaved baseline and candidate samples on the same inputs and report medians, spread, failures, memory and binary size. Acceptance: `cargo test -p myoci --test mirror locked_acquisition -- --exact`. Search callers and persisted consumers before removing any replaced helper or cache; delete only proven-dead paths. Review the changed OCI scope through the `ultrareview` lenses, fix supported P1 and P2 findings, and run the close checks. Do not launch a repository-wide audit or create unrelated tickets. Final report names commands, contracts, results, operator steps, limitations and parked environment proof.

## Acceptance

The local registry fixture must serve real ORAS requests and count manifest and blob-body requests separately. Its behavior corpus is the explicit scenarios in M1–M8, not a mock of the implementation. The existing `myoci` CLI and generation tests are the compatibility oracle for import, tag, publish, verify, adopt and serving. ORAS 1.3.6 is the transport oracle. `getsentry/image-mirror` supplies the update/sync separation only: its filtered platform output and flattened destinations are intentionally not parity requirements. OCI descriptors and the existing supported-media rules are the graph oracle. For each compatibility behavior touched, compare the old and new paths on the same fixture, including errors and side effects; retain all existing passing tests.

After M7, run `cargo test -p myoci` and `make test-oci-publish` on the integrated tree. At close, rerun those checks plus `cargo test -p stuff-oci`, `make test-oci-pull`, and `make test-oci-conformance` when their prerequisites are available. Run `make test-oci-conformance-push` when push state locking changes. Run `make worker-test` and `make worker-check` only if Worker-facing code changes. The publication, pull, and conformance checks are requested because generation compatibility, serving, and push concurrency cross the changed state boundary. Keep any unavailable external prerequisite in Needs environment with its command and reason; do not report it as passing. CI must validate the same deterministic local config and lock contracts, without network access.

The final acceptance requires all local slice proofs, no unhandled conflict or integrity failure, zero upstream blob-body transfers on an unchanged second sync, stable lock and generation bytes for identical inputs, and no partial managed batch after a failure or restart. Product performance is measured but gates only in M9. A newly exposed pre-existing failure is identified with the unchanged baseline and fixed if in scope, otherwise parked with evidence; do not weaken the test.

## Needs environment

- If upstream cannot be reached or lacks required referrer enumeration, resolve and verify the real seed lock later with `myoci mirror resolve --config deploy/oci-mirror.toml --lock deploy/oci-mirror.lock`, then run the M8 consistency check. Never substitute invented descriptor metadata.
- If Docker, pinned conformance prerequisites, or a supported OS are unavailable, run the applicable `make test-oci-pull`, `make test-oci-conformance`, or `make test-oci-conformance-push` on a suitable host and report the exact missing prerequisite.
- Live R2 publication and actual consumer cutover require separate operator authority. After approval, follow `docs/PUBLISHING.md` with the documented mirror input mode, verify the promoted generation and blob availability, then update consumers separately. Local R2 simulation is not evidence of a live promotion.

## Execution boundary and non-goals

The planned contracts add CLI flags and output, versioned inventory and lock formats, managed alias ownership, crash-recoverable state metadata, shared state-lock behavior, a generation sidecar, and a deployment input mode. Existing generation formats and old input modes remain supported. The executor may make these changes within the execution grant, including a compatible TOML dependency and the explicitly requested CI validation. No product publication, live R2 modification, consumer cutover, automatic garbage collection, forced promotion, tag deletion, signature verification, platform filtering, synthesized index, or push is authorized. Fixes outside the stated defect floor require a separate request.
